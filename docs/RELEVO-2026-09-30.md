# Relevo de trabajo — MuMain S8 y Arena (30-09-2026)

## Estado comprobado

- El cliente Windows S8 de CT124 conserva una copia de su `Main.exe` anterior y tiene instalado un ejecutable compilado el 30-09-2026. SHA-256 del ejecutable nuevo: `953371E4DC285587EDA93FDE1D5F853D4601AD4B754D75E245BDD3A27163018E`.
- El código fuente cambia «Cerca» por «Cerrar», amplía los cuatro botones del menú de 108 a 160 píxeles y usa `MAX_CHARACTERS_PER_ACCOUNT` (6) en la selección de personajes. La compilación Windows x64 Release terminó correctamente. El resultado visual y la conexión dentro del juego aún requieren una prueba manual.
- La carpeta cliente recibió 20 imágenes S8 de introducción/carga y `Season8Badge.OZT`. El terreno Arena (`EncTerrain7.att` y `Terrain.att`) también quedó instalado. Los archivos S8 nuevos solo se muestran cuando el ejecutable usa las rutas introducidas en este código.
- En CT124, Arena (mapa 6) conserva 36 áreas de monstruos y 264 criaturas, más tres NPC/objetos. Doce grupos de monstruos quedaron ordenados por nivel en corrales accesibles; se abrieron doce casillas de colisión. OpenMU se reinició después de aplicar la actualización. No se ha hecho una comprobación visual dentro del mapa tras el reinicio.
- La selección automática del servidor previamente elegido y las correcciones de textos/clases están incluidas en el código fuente compilado. Su comportamiento en el cliente instalado aún requiere prueba manual.

## Pendientes para continuar

El 01-10-2026, después de instalar el `Main.exe` nuevo, el cliente mostró errores
por `Data/Effects/GlowColors.json`, `Data/Items/Models` y
`Data/Skill/unicon.jpg` (referenciado por `Rider01.bmd`). La comparación con
`src/bin/Data` mostró que la instalación carecía de 33 JSON necesarios;
`unicon.OZJ` existía en `Data/Item` pero no en `Data/Skill`. Se preparó un
parche local con esos 34 archivos y se añadió `Skill/unicon.OZJ` al proyecto
para próximas compilaciones. La instalación y la prueba en juego del parche
de datos siguen pendientes de confirmación.

1. Abrir el cliente, comprobar el menú («Cerrar» y botones sin texto cortado), los seis espacios, la selección automática del servidor, el logo y las pantallas de carga. Si el nuevo ejecutable no inicia o pierde una función S8, restaurar el `Main.exe` anterior guardado junto a él y registrar el error.
2. Entrar a Arena y confirmar visualmente acceso a los corrales, niveles y distribución de monstruos. El esquema exacto y SQL están en `docs/arena-s8/`.
3. Revisar el árbol de maestría/pentagramas S8: la compilación del código fuente pasó, pero no se verificó que tenga toda la interfaz del ejecutable S8 que se usaba antes.
4. Publicar los commits en GitHub una vez que el conector tenga acceso de escritura a `MuMain`, o desde una terminal Git autenticada. Verificar que `origin/main` apunte al último commit antes de considerar terminado el registro.
